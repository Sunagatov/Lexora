# 🇨🇳 Lexora — произношение китайского (Mandarin, zh)

**Источник:** `lexora-vocabulary (1).xlsx`; `_Lexora_Language.language=zh`, `translation_language=ru`.
**Покрытие:** 500 исходных Word ID (21361–21860), 500 объектов в JSONL; 473 предварительно `ready`, 27 `needs_review`.
**Статус:** **НЕ одобрено для автоматического импорта**. Каждый из 473 элементов `ready` структурно полный и прошёл автоматические проверки, но не был индивидуально сверён с записями носителей. 27 элементов требуют отдельной проверки. Нельзя трактовать `ready` как официальное лингвистическое подтверждение.

## 1. Правило произношения

Каноническое представление — **Hanyu Pinyin со знаками тонов**; в настоящем наборе syllable-spaced Pinyin (слоги разделены пробелами для облегчения чтения), например `nǐ hǎo`. Это не IPA; знаки и основной фонетический смысл стандартного Pinyin сохранены. Слово/фраза на упрощённых иероглифах не заменяется переводом или иным иероглифом.

Дополнительная **русская транскрипционная подсказка** находится отдельно (`lexora-zh-russian-reading-hints.jsonl`) и содержит тон **для каждого слога**; она не служит точной фонетической записью и не должна заменять основное поле Pinyin. Основная JSONL структура фиксирована первоначальным заданием Codex; дополнительные записи отделены, чтобы не подмешать их в IPA, прежние Pinyin или Notes.

## 2. Тоны и запись

| Pinyin | Русский образец | Правило |
| --- | --- | --- |
| mā (1) | ма¹ | высокий ровный тон |
| má (2) | ма² | восходящий тон |
| mǎ (3) | ма³ | низкий, часто с подъёмом в изоляции |
| mà (4) | ма⁴ | резкий нисходящий тон |
| ma (0) | ма⁰ | нейтральный: короткий, без собственного тона |

Примеры **только из этого экспорта**: `你好 → nǐ hǎo → ни³ хао³` (в речи обычно ní hǎo); `谢谢 → xiè xie → се⁴ се⁰`; `银行 → yín háng → инь² хан²`; `妈妈 → mā ma → ма¹ ма⁰`.

В непрерывной речи тон меняется: третьи тоны подряд, `bù` перед 4-м тоном, `yī` в различных позициях. Канонический Pinyin в записях в основном сохраняет исходные (словарные) тоны, а специальные контекстные изменения описаны примечаниями и здесь. **Не менять Pinyin в приложении без сравнения с уже хранимым Pinyin.**

## 3. Русское чтение сложных звуков

- **j / q / x** (например, `jī / qī / xī`) приблизительно `цзи / ци / си`, но реальная артикуляция мягче и отличается от русского.
- **zh / ch / sh / r** — ретрофлексные (заднеязычно-кончикоязычные) звуки; приблизительные `чж / ч / ш / ж` не полностью передают их.
- **z / c / s** — `цз / ц / с`; `zi, ci, si` условно записаны `цзы, цы, сы`, **не** как обычные русские слоги.
- **ü** (`nǚ, lǜ`) — передний округлённый гласный, ближе к немецкому ü или французскому u; не обычное «ю».
- **-n / -ng** — разные окончания: `-n` передний носовой, `-ng` задний носовой (без произносимого г).
- Русские подсказки с индексами ¹²³⁴⁰ — **вспомогательные**, их нельзя импортировать в базовый Pinyin.

## 4. Контекст, многозначность и примеры исправлений

- `银行`: банк → **yín háng**, не *yín xíng*.
- `银行卡`: банковская карта → **yín háng kǎ**.
- `便宜`: недорогой → **pián yi**, не *biàn yí*.
- `咳嗽`: кашель → **ké sòu**, не *hāi sòu*.
- `地板` / `地址`: **dì**, не *de*.
- `睡觉`: **shuì jiào**, не *shuì jué*.
- `长`: «длинный» → **cháng**, не *zhǎng*.
- `牛仔裤`: джинсы → **niú zǎi kù**, не *niú zǐ kù*.
- `假期`: отпуск → **jià qī**, не *jiǎ qī*.
- `谢谢`: второй слог нейтральный **xie**.
- `画` встречается с разными Word ID как noun/verb. Идентификаторы сохранены.

Реестр 74 отличий от базовой автоматической транслитерации ICU находится в `lexora-zh-pinyin-corrections.csv`; он включает нейтральные тоны, исправления полифонических знаков и сегментацию слогов. Не все отличия являются исправлениями *ошибок*: многие — лишь различия конвенций записи.

## 6. Экспорт и безопасность импорта

1. Не запускать импорт до проверки источника, статусов и полей в текущей Lexora DB.
2. Убедиться, что не будет перезаписи существующих IPA, Pinyin, аудио, переводов, Meaning, Topics, Knowledge и learning progress.
3. Основной JSONL содержит **строго** `word_id`, `language`, `term`, `part_of_speech`, `pronunciation_easy`, `pronunciation_note_ru`, `status`, `issue`. При `needs_review` значение `pronunciation_easy=null` и конкретная причина в `issue`.
4. Отдельный overlay JSONL с русскими подсказками нельзя автоматически вставлять в уже используемые поля без миграции и проверки модели данных.
5. `ready` в JSONL = подготовлено к последующей экспертной проверке, НЕ разрешение на импорт. Для импорта необходима явная проверка преподавателя/носителя по выборке, все 27 ошибок закрыты, а затем решение владельца данных.
6. Иерархию тем, Word ID, формы слова и POS не менять.
